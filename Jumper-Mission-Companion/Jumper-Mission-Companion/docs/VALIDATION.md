## UI and recognition checks

The dashboard checks cover desktop/mobile layout, typed-command routing, Escape, focus pause/resume, a memory-game answer, mission start/stop, and successful loading/inference of the real local MediaPipe model on a blank frame (zero hands expected). Separate native UI checks cover the displayed MuJoCo frame, exact dance mode, cancellation and mission completion.

Synthetic landmark fixtures verify open palm, fist and V-sign rules under scale/translation/rotation changes, malformed landmarks, dwell filtering and held-sign suppression. They are not webcam accuracy measurements. The voice parser tests exact vocabulary, rejection of descriptive/negated phrases and confidence thresholds. They are not acoustic speech-recognition measurements.

## Remaining acceptance on your laptop

1. Run setup and the native dashboard on Windows; verify its own OpenGL rendering and the supplied Windows controller extension load correctly.
2. Enable the camera yourself. Check each gesture with both hands, several distances and normal room lighting; confirm no unintended turns and prompt tracking-loss handling. Do not call this production-quality recognition until these observations support it.
3. Enable the microphone yourself. Check supported commands with your accent, background noise and the actual browser speech service. If unsupported, the UI explains that and typed commands remain available.
4. Confirm performance while moving between panels and switching activities; leave the page and verify cancellation. A long host-loop stall cancels activities rather than replaying stale actions after wake.
5. Physical robot deployment, real sensors, unknown-map perception/SLAM, custom trained policies, simulator-to-hardware transfer and BE UNLIMITED native `.app` packaging have **not** been implemented or certified here.

The project is a tested local simulation build with device-dependent checks remaining. It must not be described as perfect, hardware tested, or fully competition ready.
